## Добавить лицензирование Runlith

Применить выбранную модель без изменений runtime, тестов, версии продукта и TASK-0087-R1.

1. **Проверить актуальный working tree и существующие notices.** Сохранить все незакоммиченные изменения. Не менять лицензию стороннего кода и зависимостей. В текущем Cargo workspace отдельного Plugin SDK нет; внутренние IPC/planner contracts автоматически SDK не считаются.
2. **Добавить корневой `LICENSE` с неизменённым официальным текстом PolyForm Shield 1.0.0.** Получить полный текст из репозитория PolyForm, а не восстанавливать его из краткого веб-пересказа. Проверить точное соответствие исходнику. Не выдумывать юридическое лицо, copyright holder или контакт.
3. **Добавить `LICENSING.md` с областью действия.** Shield — лицензия по умолчанию для собственного Community-кода репозитория, если конкретный файл/компонент явно не помечен иначе; сторонние компоненты сохраняют свои условия. Прямо указать source-available, а не OSI open source.
4. **Описать коммерческую модель, не выдавая её за готовый договор.** Отдельно оговорить, что дополнительные OEM/white-label/платные права предоставляются только отдельным согласованным коммерческим соглашением. Не создавать фиктивную юридически утверждённую EULA, не объявлять существующий Shield-код платным задним числом. Условия бессрочной Pro Local и вкладов требуют последующей договорной проработки.
5. **Apache-2.0 — только для будущего явно выделенного SDK.** Внести эту границу в документацию; не применять Apache ко всему репозиторию или внутренним контрактам. Если добавляется справочный полный текст Apache-2.0, явно указать, что само наличие текста не даёт выбрать Apache вместо Shield для ядра. На данном этапе предпочтительно ограничиться ссылкой на официальный текст, пока нет компонента, к которому он применяется.
6. **Связать документы.** Добавить короткий раздел License в README и согласовать раздел лицензирования канонического документа монетизации с выбранной моделью, сохранив требование юридической проверки до публичного выпуска. Если целевые документы уже изменены другим участником, не перезаписывать пересекающиеся правки.
7. **Проверить результат.** Проверить ссылки/пути, точность текста LICENSE, отсутствие противоречивого MIT/Apache grant для ядра, `git diff --check` и итоговый список изменений. Runtime не меняется, поэтому повторный workspace test suite для этих документов не требуется.

Результат: действительный стандартный Shield-текст и понятные границы лицензирования в проекте; коммерческие договоры и лицензирование отсутствующего SDK не будут выданы за уже реализованные. Коммитов, push и публикации не будет.
